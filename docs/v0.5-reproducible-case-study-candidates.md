# v0.5 Reproducible Case-Study Candidates

EvidenceForge reaches v0.5 when it has two or three representative case studies that can be audited or rerun from data table to model output.

The target is not just "good papers". The target is:

```text
published article -> public data/code -> table schema -> model script -> output artifact -> reusable skill rule
```

## Selection Criteria

Prioritize papers that satisfy most of these conditions:

- high-value journal or influential field journal;
- clear analysis form: first-order meta-analysis, second-order meta-analysis, meta + ML, Bayesian meta-analysis, or mega-analysis;
- open data in Zenodo, OSF, Figshare, GitHub, Dryad, or source data files;
- open R/Python code or enough model description to reconstruct the workflow;
- reusable data schema;
- explicit model objects such as `metafor::rma.mv`, `rma`, `gbm`, `ranger`, `plspm`, `brms`, `nnet`, or Bayesian hierarchical model scripts;
- manageable enough to convert into an example workflow.

## Recommended v0.5 Package

To make EvidenceForge v0.5 credible, use three complementary examples:

### Case 1: Potassium Fertilization NC

Purpose:

```text
first-order treatment-control meta-analysis
```

Expected deliverable:

```text
examples/potassium-nutrient-meta/
  data/
  scripts/
  outputs/
  walkthrough.md
```

Core reproducible chain:

```text
Crop yield.csv + SOC.csv
-> compute lnRR
-> build Study_ID / Entry_ID
-> run rma.mv
-> run BRT / gbm
-> export tables and figures
```

### Case 2: Riparian Buffers NC

Purpose:

```text
biodiversity meta-analysis with protected raw data but public processed data/code
```

Core reproducible chain:

```text
Zenodo processed effect-size data
-> R scripts organize data
-> run meta-analysis
-> run buffer-width analysis
-> reproduce key results/plots
```

This is useful because many ecological syntheses cannot publish all raw species-by-site data, but can still publish processed effect-size data and scripts.

### Case 3: Agricultural Diversification NC

Purpose:

```text
second-order meta-analysis / umbrella-style synthesis
```

Core reproducible chain:

```text
review-level effect table
-> overlap and quality checks
-> duration meta-regression
-> sensitivity datasets
-> yield-service trade-off model
```

This makes EvidenceForge distinct from ordinary first-order meta-analysis toolkits.

## Optional Case 4: Meta + ML / Omics

Use the Parkinson's gut microbiome paper after Priority A:

```text
multi-cohort microbiome profiles
-> harmonized taxonomic/functional features
-> ML classification/importance
-> meta-level interpretation
```

This can become the first "meta-analysis + machine learning + omics" branch.

## Implementation Plan

### Step 1: Build case-study folders

Create:

```text
examples/
  potassium-nutrient-meta/
  riparian-buffer-biodiversity-meta/
  agricultural-diversification-second-order-meta/
```

Each case should contain:

```text
README.md
data-inventory.md
analysis-form-fit.md
reproduction-log.md
scripts/
outputs/
```

### Step 2: Do not rewrite original author code first

First run or inspect the original code as-is. Only then create a clean EvidenceForge version.

### Step 3: Record reproduction verdicts

Use:

```text
fully rerunnable
partially rerunnable
figure-only reproducible
data-schema reusable
conceptual only
```

### Step 4: Convert findings into reusable skills

Each case should contribute at least one reusable artifact:

- coding schema;
- R workflow blueprint;
- model-spec ledger;
- output checklist;
- reviewer-proof guardrail.

## Bottom Line

The fastest route to v0.5 is:

```text
Potassium NC + Riparian Buffers NC + Agricultural Diversification NC
```

This trio covers:

- first-order treatment-control meta-analysis;
- ecological biodiversity meta-analysis with processed-data reproducibility;
- second-order meta-analysis with overlap, quality, duration, and trade-off logic.

After that, add:

```text
Ant soil carbon NC + Parkinson's microbiome ML meta-analysis
```

to make EvidenceForge distinctive in ecological mechanism synthesis and meta + ML workflows.
